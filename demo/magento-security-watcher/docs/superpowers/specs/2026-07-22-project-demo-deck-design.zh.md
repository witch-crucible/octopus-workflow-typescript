# Magento2 Security Watcher — 项目演示页设计规格

**日期：** 2026-07-22  
**状态：** 已批准（待实现）  
**交付物：** 独立静态 HTML 分屏演示（非 PPT、不挂载 `msw serve`）

## 1. 目标

为**技术/运维同事 + 业务/管理层**提供一份可双击打开的网页演示，讲清：

1. 项目作用与优势  
2. 主要流程  
3. 技术架构  
4. AI 的作用（表述为「引入 AI 分析」）  
5. 尽量量化；无法量化处用形容词

## 2. 非目标

- PowerPoint / Keynote  
- 挂进 Web 看板路由（如 `/demo`）  
- 依赖 CDN 才能翻页（允许可选字体 CDN，须有系统字体 fallback）  
- 页脚数据来源/日期脚注  
- 演示页展示 git token、API Key 等密钥  
- 自动从 SQLite 热更新数字（v1 把实数写死进 HTML；日后可另加生成脚本）

## 3. 受众与叙事

| 前半 | 后半 |
|------|------|
| 痛点、价值、流程总览、量化 | 架构、入库、扫描、AI、通知与看板 |

用词统一：对外文案用「**通知**」，不用「告警」。优势第三条写「**引入 AI 分析**」，不写「AI 只叙述不裁决」。

## 4. 交付形态

- **路径：** `docs/demo.html`（单文件，内嵌 CSS + 少量 JS）  
- **交互：** 全屏分屏；`←` / `→`、空格翻页；底部页码 + 可点击圆点跳转；推荐浏览器全屏演示  
- **视觉：** 对齐看板「夜航雷达」调性——冷灰蓝底、teal 强调、IBM Plex 或系统字体 fallback；避免紫霓虹、奶油 Terracotta、满屏 pill  
- **打开方式：** 本地文件协议或任意静态服务器均可

## 5. 分屏大纲（11 屏）

| # | 标题 | 内容要点 |
|---|------|----------|
| 1 | 封面 | 产品名 + 一句话：Magento2 安全情报入库 → 多项目确定性核验 → 企微去重通知 |
| 2 | 痛点 | 公告散、店多、手工对照易漏；定性：易漏、难追溯、响应慢 |
| 3 | 价值 / 优势 | ① 风险项级跟踪 ② 版本 + 内容指纹双层证据 ③ **引入 AI 分析**；能写则写真实库存数字（配置项目数、公告数、RiskItem 数等） |
| 4 | 主流程总览 | 横向链路：`ingest → RiskItem → scan → Finding → notify（通知）` |
| 5 | 技术架构图 | 见 §6；一屏可读的模块框图（SVG 或纯 CSS），无外部图库 |
| 6 | 情报入库 | Bulletin 拆 RiskItem；官方公告 + NVD + 补丁；展示当前库实数（实现时查询） |
| 7 | 项目扫描 | git 拉取配置分支 → Magento 库存版本 → 对照 RiskItem 出 Finding；确定性版本/指纹判定 |
| 8 | AI 作用 | **引入 AI 分析**：中文业务叙述、结构化辅助、指纹草稿；与确定性匹配如何分工（分析辅助 vs 结论由规则落地） |
| 9 | 通知与看板 | 企微通知去重；只读 Web 看板（示意即可，不嵌入真实服务） |
| 10 | 量化一览 | 表格汇总真实数字；无 Finding / 扫描跑次等则标「尚未产生」或省略该行，改用定性一句 |
| 11 | 收尾 | 下一步（扩大项目配置、cron）；如何打开本页 |

## 6. 技术架构图（第 5 屏）

示意关系（实现时画成清晰框图，节点中文+模块名可选）：

```text
[Adobe 公告 / NVD / 补丁]
        │
   AdvisoryIngest ── LLM（引入 AI 分析：叙述 / 指纹草稿）──► RiskItem + 报告
        │
        ▼
   SQLite Store ◄── MagentoInventory / 版本+指纹匹配
        │                    ▲
        │              GitWorkspace（配置项目）
        ▼
   Finding（确定性结论）──► WeCom 通知（去重）
                        └─► Web 看板（只读）
```

## 7. 量化规则

1. **优先真实数据：** 实现时从 `config/projects.yaml` 与 `data/db/watcher.sqlite`（若存在）读取：启用项目数、公告数、RiskItem 数、Finding 按状态计数、扫描跑次等，写入 HTML。  
2. **无法量化：** 用形容词（如「更快发现」「更少漏检」「结论可追溯」），不编造「每周省 X 小时」类假精确数字。  
3. **敏感信息：** 仅展示项目 `id` / `name`；禁止回显 git URL 中的凭据。  
4. **不展示**数据来源脚注或「示意/截至某日」类页脚说明。

## 8. 验收标准

1. 双击或用浏览器打开 `docs/demo.html` 即可演示，无需 `msw serve`。  
2. 键盘可翻完 11 屏；架构图一屏内可读。  
3. 文案：用「通知」；优势含「引入 AI 分析」。  
4. 有真实库存数字处与当前库/配置一致（实现当日快照）；无数据处不编造精确业务收益数字。  
5. 页面无密钥明文；无数据脚注。
